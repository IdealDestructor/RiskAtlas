# 舆图 · 产品需求文档（PRD）

> 版本：v1.0（重构基线） · 状态：待评审 · 更新日期：2026-07-28

## 1. 背景与愿景

### 1.1 原项目盘点

原「舆图」是一个企业风险可视化项目（Vue 2 + ECharts 4 + 百度地图），核心能力：

- 基于静态数据库与前瞻开放平台 API，展示企业主体信息、失信被执行人记录、司法判决、质检新闻等；
- 通过 ECharts 图表与 POI 地图呈现区域、行业维度的风险分布；
- 附带一套实体识别 NLP 数据集（train/test/实体词典）作为分析原料。

**根本局限**：数据静态、时效性差；风险判断依赖人工读表，无智能归纳；数据源单一，无法覆盖实时舆情；交互为"查数式"，缺乏分析引导。

### 1.2 重构愿景

将「舆图」重构为 **LLM 驱动的实时实体风险情报平台**：

用户输入一个查询词（公司名、品牌、人物、行业关键词），系统实时检索多源新闻与舆情数据，由大模型完成实体消歧、事件抽取、情感研判与风险归类，经可解释的风险评分引擎聚合后，以流式方式呈现多维可视化驾驶舱与 AI 风险研报，辅助金融机构完成授信尽调、投后监控与风险预警。

**一句话定位**：输入一个名字，30 秒内得到一份有数据支撑、可下钻溯源、可持续监控的实体风险画像。

### 1.3 设计取舍

| 维度 | 原方案 | 新方案 |
| --- | --- | --- |
| 数据时效 | 静态库，离线导入 | 实时检索 + 可选持久化快照 |
| 分析方式 | 人工读表 | LLM 结构化抽取 + 确定性评分引擎 |
| 数据源 | 单一 API + 本地数据集 | 多源适配层（新闻搜索/RSS/GDELT/垂直源） |
| 呈现 | 整页静态图表 | 流式渐进渲染的驾驶舱 + 可追问研报 |
| 风险结论 | 无 | 六维可解释风险评分 + 等级 + 证据链 |

## 2. 目标用户与核心场景

### 2.1 用户画像

- **对公信贷经理**：授信前快速尽调，需要"值不值得深查"的初筛结论；
- **风控/合规分析师**：投后与存续期监控，需要异常信号与预警；
- **投研人员**：标的舆情面扫描，需要事件时间线与情绪拐点；
- **合作方评估人员**：合作前背景调查。

### 2.2 核心场景（User Story）

1. **US-1 快速尽调**：信贷经理输入"某某科技有限公司"，30 秒内看到风险总分与六维雷达、近 90 天负面事件时间线、Top 风险信号及原文证据链接，决定是否需要人工深查。
2. **US-2 证据溯源**：分析师点击某个风险信号，展开支撑该信号的原始新闻列表，核对来源可信度与发布时间，避免被 AI 误判误导。
3. **US-3 研报导出**：用户阅读自动生成的流式风险研报，就"司法风险为什么偏高"继续追问，系统将问答纳入报告上下文，最终导出 PDF/链接分享。
4. **US-4 持续监控**：风控将 20 家存量客户加入监控列表，系统定时重跑分析，风险分数跨阈值或出现高严重度新事件时推送预警。
5. **US-5 横向对比**：用户对比同行业两家候选供应商的风险画像，辅助准入决策。

### 2.3 场景边界（本期不做）

- 不构成投资建议，不输出"放贷/拒贷"决策，只提供情报与参考评分；
- 不做全量企业库检索（无工商全量数据授权），实体识别以新闻语料消歧为主；
- 不承诺对封闭源（裁判文书网、征信系统）的实时覆盖，P1 起以合规授权 API 形式接入。

## 4. 风险指标体系（业务视角）

### 4.1 六维风险分类法

| 维度 | 典型事件 | 示例关键词 |
| --- | --- | --- |
| 司法诉讼 | 被诉、败诉、被执行、失信、股权冻结 | 判决、执行、冻结、仲裁 |
| 财务信用 | 债务违约、流动性危机、审计非标、评级下调 | 违约、逾期、爆雷、退市 |
| 监管合规 | 行政处罚、立案调查、牌照风险、数据违规 | 处罚、立案、整改、约谈 |
| 经营治理 | 高管动荡、大规模裁员、供应链断裂、实控人变更 | 辞职、裁员、停产、易主 |
| 产品质量 | 召回、质量事故、安全事故、大规模投诉 | 召回、缺陷、事故、投诉 |
| 声誉舆情 | 负面曝光、公关危机、高管丑闻、抵制 | 曝光、翻车、抵制、道歉 |

### 4.2 信号属性

每条风险信号（Signal）携带：维度、严重度（1-5）、置信度（0-1）、首末次报道时间、证据文章集合、来源可信度、情绪倾向。评分算法与参数见 [ARCHITECTURE.md](./ARCHITECTURE.md) 第 6 节。

### 4.3 结论免责与可信度表达

- 所有分数旁标注样本量（纳入分析文章数）与信息覆盖度提示；
- 样本不足（如 <5 篇相关文章）时总分降级为"信息不足"，不输出确定等级；
- 报告固定输出"信息缺口与局限"段落。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏反馈 < 2s（管线进度可见）；完整分析 P50 < 45s，P95 < 90s；面板渐进渲染 |
| 成本 | 单次分析 LLM 成本可配置上限（默认 ≤ ¥0.5/次）；文章批量并发分析 + 摘要压缩控制 token |
| 可靠性 | 任一数据源失败不阻断整体（降级并标注）；LLM 结构化输出校验失败自动重试 ≤2 次后跳过该篇 |
| 可观测 | 管线各阶段耗时/成功率/成本打点；分析任务全链路 trace 可查 |
| 安全合规 | API key 仅服务端持有；文章正文仅缓存 24h（版权友好，存摘要与元数据）；robots 协议尊重；免责声明常驻 |
| 国际化 | 界面中文优先；检索与分析支持中英文语料 |
| 兼容 | 桌面优先（金融场景），响应式兼容平板；现代浏览器 |

## 6. 成功指标

- 端到端分析完成率 ≥ 90%（排除用户主动取消）；
- 信号证据点击率 ≥ 15%（说明用户在做溯源，产品可信）；
- 研报"有用"反馈率 ≥ 70%；
- 监控实体 7 日留存（P1）：≥ 40% 的监控实体在一周后仍被查看。
